数据库实践大作业统一参考文档 (openGauss/openEuler)

I. 项目背景与技术环境

1.1 大作业系统设计背景

本项目目标是为某高校设计和建设**校园一卡通消费系统**的数据库，实现数字化、便捷化管理。

**核心管理对象包括：**用户（学生/教职工）、校园一卡通卡片、消费商户、消费记录、充值记录。

**系统核心功能要求（通过程序实现）：**用户信息查询、一卡通卡片状态查询、商户信息查询、指定商户的营业/停业设置、消费记录查询、充值记录查询、一卡通余额查询等。

II. 数据库设计要点 (逻辑与物理)

2.1 需求分析与数据字典要点

需求分析阶段需要输出 0~1 层数据流图和**数据字典**，数据字典应包含数据项、数据结构、数据流、数据存储和处理过程 5 部分。

**核心数据项/结构参考：**

| 类别                       | 描述要点                                                     | 来源/参考 |
| -------------------------- | ------------------------------------------------------------ | --------- |
| **用户** (User)            | 姓名、身份证号（教职工/学生证件号）、联系方式、登录密码、电子邮箱、用户类型（学生/教职工） |           |
| **卡片** (Card)            | 唯一卡号、卡片状态（正常、挂失、注销）、办卡时间、所属用户信息、**实时余额** (累计充值-累计消费) |           |
| **商户** (Merchant)        | 商户编号、商户名称、商户类型（食堂、超市等）、商户位置、营业状态（营业/停业） |           |
| **消费记录** (Consumption) | 消费编号、卡号、商户编号、消费金额 (不可为负数)、消费时间、消费备注 (可选) | ,         |
| **充值记录** (Recharge)    | 充值编号、卡号、充值金额 (不可为负数)、充值方式（线下/线上）、充值时间、充值状态（成功/失败） | ,         |

2.2 逻辑结构设计 (关系模式与规范化)

关系模式需要满足**第三范式 (3NF)** 要求。

**核心关系描述要点 (基于系统关系说明)：**

1. 一个用户可办理**一张主卡**,。
2. 一张卡片可关联**多条**消费记录。
3. 一张卡片可关联**多条**充值记录。
4. 一个商户可关联**多条**消费记录。

2.3 物理结构设计 (约束要点)

在物理模型中，需要根据逻辑设计模型定义数据表结构，并添加必要的约束。

| 表格           | 字段/对象      | 约束类型           | 要求/说明                | 来源/参考 |
| -------------- | -------------- | ------------------ | ------------------------ | --------- |
| **卡片表**     | 余额属性       | CHECK (余额 >= 0)  | **一卡通余额不可为负数** |           |
| **卡片表**     | 所属用户       | 外键 (Foreign Key) | 关联用户表               |           |
| **消费记录表** | 消费金额       | CHECK (金额 > 0)   | 金额不可为负数，大于 0   |           |
| **消费记录表** | 卡号, 商户编号 | 外键 (Foreign Key) | 关联一卡通卡片表和商户表 |           |
| **充值记录表** | 充值金额       | CHECK (金额 > 0)   | 金额不可为负数，大于 0   |           |
| **充值记录表** | 卡号           | 外键 (Foreign Key) | 关联一卡通卡片表         |           |

III. openGauss 数据库安装与连接

3.1 openGauss 安装部署流程 (单机版)

openGauss 安装部署主要包含 4 个阶段：ECS 购买、OS 配置修改、openGauss 安装、数据库使用。

| 阶段              | 核心操作步骤 (仅列举关键技术点)                              | 角色     | 来源/引用 |
| ----------------- | ------------------------------------------------------------ | -------- | --------- |
| **1. ECS准备**    | 购买 openEuler 20.3 LTS ARM 架构的 ECS,。                    | Root     | ,         |
| **2. OS配置**     | 登录服务器 (SSH 或 CloudShell)。设置字符集参数 `LANG=en_US.UTF-8`。修改 Python 软连接到 `python3` (需为 3.7.x 版本)。安装 `libaio` 包。 | Root     |           |
| **3. 数据库安装** | 创建安装目录 `/opt/software/openGauss`。下载数据库安装包 (`wget`命令)。创建并配置 `clusterconfig.xml` (需配置主机名、私有 IP、路径，`clusterType`为 `single-inst`),。使用 `gs_preinstall` 准备环境，创建 `omm` 用户互信 (需设置 `omm` 密码),。切换至 `omm` 用户并执行 `gs_install` 安装数据库 (需设置数据库管理员密码，如 `openGauss@123`),。 | Root/omm | ,,        |
| **4. 数据库使用** | 切换至 `omm` 用户，使用 `gs_om -t start` 启动服务,。使用 `gsql -d postgres -p 26000 -r` 连接数据库。 | omm      |           |

3.2.2 Data Studio 图形化连接 (JDBC/ODBC 前置)

为了使用 Data Studio 或进行远程编程连接，需要修改数据库服务器配置和 ECS 安全组。

1. **修改** **pg_hba.conf****：** 增加一行 `host all all 0.0.0.0/0 sha256`，允许远程连接和加密认证。使用 `gs_guc set -N all -I all -h "host all all 0.0.0.0/0 sha256"` 命令实现,。
2. **修改** **postgresql.conf****：** 将 `listen_addresses` 值修改为 `'*'`，允许监听所有 IP 地址。使用 `gs_guc set -I all -c "listen_addresses='*'" ` 命令实现,。
3. **重启数据库** 使配置生效,。
4. **ECS 端口放开：** 在华为云控制台的安全组入方向规则中，**添加 TCP:26000 端口**。
5. **Data Studio/JDBC 依赖：** Data Studio 5.1.0 需要 **JDK 11 及以上**环境,。

3.3 数据库创建与 Schema 设置

作业要求创建项目数据库和 Schema：

1. **创建数据库：** `CREATE DATABASE campus_card ENCODING 'UTF8';` (数据库编码需为 UTF-8),。
2. **连接并创建 Schema：** 连接到 `campus_card` 数据库后，执行 `CREATE SCHEMA campus_card;`,。
3. **设置搜索路径：** `SET search_path TO campus_card;` (将 `campus_card` 设置为当前默认 Schema),。

VI. 编程连接与二次开发参考

6.1 JDBC/ODBC 连接

**JDBC/ODBC 连接步骤的共同前置条件** (需在数据库服务器端完成):

1. 修改 `pg_hba.conf` 和 `listen_addresses`,。
2. 确保 ECS 安全组中 **26000 端口**已放开。
3. 安装并配置 **JDK 11.0.17** 及以上环境（如果尚未配置）,,。

**JDBC 连接步骤核心：**

1. 下载 JDBC 驱动包 (例如 `openGauss-5.0.1-JDBC.tar.gz`)。
2. 在 Java 代码中引入驱动类 `org.postgresql.Driver`，使用 URL 格式连接：`jdbc:postgresql://<弹性公网 IP>:<端口>/<数据库名>?ApplicationName=app1`。
3. 编译并运行 Java 代码，例如使用 `javac -encoding utf-8 -cp /path/postgresql.jar openGaussDemo.java` 和 `java -cp .; /path/postgresql.jar openGaussDemo`,。

**ODBC 连接步骤核心：**

1. 在 Linux 或 Windows 客户端配置 ODBC 数据源 (DSN),。
2. Linux 环境需安装 `unixODBC` 源码包并配置 ODBC 驱动文件 (`odbcinst.ini`) 和数据源文件 (`odbc.ini`),。
3. 使用 C/C++ 代码调用 ODBC API 连接数据库和执行 SQL。

6.2 openGauss 开源二次开发

如果需要进行二次开发，例如实现 `gauss_hello` 函数：

1. **社区环境准备：** 注册码云账号，绑定主邮箱，并签署 **CLA 贡献者协议**。
2. **拉取代码：** Fork openGauss-server 和 openGauss-OM 到个人仓库，然后克隆到本地 (Windows 或 Linux),。
3. **开发环境配置：** 安装 Git 和 VSCode/C/C++ 开发工具,。
4. **代码修改：** 修改 `varlena.cpp`、`builtins.h`、`builtin_funcs.ini`、`pg_proc.h` 等文件，实现新函数并注册到系统表 (例如，为新函数分配唯一的 OID，如 9981),,。
5. **代码提交：** 使用 `git add .`, `git commit -m "..."`, `git push` 将本地修改提交到个人远程仓库。
6. **编译环境要求：** 编译 openGauss 推荐使用 **openEuler 20.3 LTS ARM** 架构的 ECS，建议配置为 **8vCPUs|32GiB** 或更高 (12vCPUs|48GiB)。
7. **编译：** 安装软件依赖，下载第三方二进制库，使用 `openGauss-server/build.sh -m release -3rd /path/binarylibs -pkg` 进行一键编译和打包,。
8. **验证：** 使用编译后的安装包部署数据库，连接后执行新函数进行验证，例如 `select gauss_hello('openGauss User');`
